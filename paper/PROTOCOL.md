# Experimental protocol v0.1 — planned, not executed

Freeze the final protocol, dataset IDs, sample manifests and analysis code before held-out runs. Log any deviation and its reason. This document sets planned sample counts and operating points; these are not observed measurements.

## Questions and estimands

RQ1 measures disagreement and its privacy effect, RQ2 localizes a reproducible discrepancy, RQ3 measures time until a validated model is ready, RQ4 measures guard detection/overhead/refusal, and RQ5 measures public-data redaction and restoration. PyTorch fp32 is the **numerical reference**, not the gold privacy oracle. Human/dataset PII annotations determine recall and leakage.

Use two paired contrasts: (A) exactly the same ONNX bytes and input tensors on different providers, to isolate runtime/backend behavior; (B) each precision/export against the original PyTorch checkpoint, to measure conversion plus quantization effects. Add native CPU inference of each ONNX artifact as a bridge. Do not infer backend bugs from B alone. For GLiNER, retain original span scores and compare identical label prompts, tokenization, span construction, thresholds and decode policy. If reporting token agreement, deterministically project decoded spans to a common gold character/word grid, with a declared overlap priority. It is not directly comparable to DistilBERT subword argmax; report these token measures separately.

This is **not an executable full factorial**: OS, memory, operator and browser availability remove cells. Generate an explicit cell list after capability probes and report attempted/supported/completed/failed/unsupported counts. Never replace an unsupported static-int8 graph with dynamic int8 under the same label. For static quantization, freeze a train-only representative calibration slice and its hash; compare per-tensor/per-channel weight scales as a nested RQ2 factor. Inspect packed 4-bit graph coverage before inclusion. List unavailable variants and reasons even if none executes.

Stage 1 reproduces DistilBERT on the original Apple configuration/current host; stage 2 checks both models on all owned devices and available browsers; stage 3 extends the same artifact set to lab Intel/NVIDIA/AMD/second Android. A reduced paper must state its narrower scope explicitly. Unsupported operators/memory limits are measured deployment outcomes, not numerical failures.

### Measures and denominators

| Measure | Numerator / denominator | Required breakdown |
|---|---|---|
| Content-token agreement | matching reference labels / non-padding, non-special positions | model, artifact, provider, browser, device, language, length; historical special-inclusive score separately |
| Pairwise backend disagreement | unequal labels / aligned eligible positions for the same artifact and tensors | include label confusion matrix, PII→O transitions, per-document disagreement, repeat variability |
| Numerical distance | absolute/max and relative L2 logit/score differences over finite aligned outputs | relative denominator floor 1e-12, top-two margin, non-finite and shape failures separately; no universal fp tolerance used to define a bug |
| Entity recall / precision / F1 | correctly covered gold entities / all policy-required gold entities; correct predicted spans / all predicted spans | strict typed exact spans and untyped full character-coverage recall separately; report partial exposures and micro/macro per document/type |
| Exact value leak | gold sensitive value instances still present in outgoing payload / all eligible gold value instances | occurrence and unique-value-by-request scores separately; conservative partial-value/character exposure secondary; policy and normalization frozen |
| Request leak rate | sent requests exposing at least one gold sensitive value / all evaluated eligible requests | also conditional on sent requests, and number blocked/failed/unavailable; never exclude refusals silently |
| Silent harmful acceptance | sends with a fault-induced excess leak and no error/refusal / all fault-exposed eligible requests | paired no-fault control, natural vs injected faults, guard arm; annotation/model failures separated |
| Availability | successfully sent safe requests / eligible requests | no inference that blocking all requests is a useful guard |

Inspect **the serialized outgoing request body at the local send boundary**, not only an intermediate redacted string. Keep all trials local initially with a stub transport that captures payloads. Structured/rule-only, model-only, hybrid, and dictionary-enabled policies are distinct arms. Freeze the entity-type crosswalk for each dataset (including TAB DIRECT/QUASI/NO_MASK). Report unsupported label classes in the denominator or a clearly separate coverage stratum; do not drop difficult classes to improve recall. Long-value repeats, punctuation, Unicode, overlapping annotations and window boundaries need character-offset validation. For leak scoring, preserve exact value presence as primary; define NFC/case/spacing canonicalization and partial components in separate scores. A generic substring match alone can miscount a public homonym, so inspect offsets/context for sampled disagreements.

Compute paired differences per document and stratified bootstrap 95% confidence intervals over independent documents (planned 10,000 bootstrap resamples, frozen seed). Cluster repeated mentions and annotation versions by source document. For rare events, show counts and uncertainty; do not treat correlated tokens as independent Bernoulli samples. When a zero-event binomial bound is shown, disclose the independence assumption and eligible N. Device strata are fixed hardware cases, not a representative sample of all devices. Primary endpoints: content-token disagreement, full-coverage entity recall and request/value leak deltas. Secondary precision/latency/guard comparisons are exploratory unless pre-specified; do not manufacture significance across hundreds of cells.

## RQ2 localization

See rq2/README.md and the diagnostic harness. Verify model hash, token IDs, masks, padding and label order first; bypass tokenization with pre-encoded tensors. Compare ONNX CPU/WASM/WebGPU on identical bytes, optimization disabled/all, then controlled graph fusions. Inspect original/optimized operator inventories and actual placement. Priority hypotheses are integer signedness/zero-point handling, partition transfers, dynamic min/max scales, accumulation/precision and graph transformation. The absent WebGPU registrations for DynamicQuantizeLinear/MatMulInteger in ORT 1.30 are a placement clue, not a causal result. Bisect versions only after a failing artifact/input is preserved. Extract the earliest divergent subgraph and replay captured real activations, then shrink dimensions/constants while preserving the mismatch. Synthetic arithmetic cases alone do not reproduce the NER failure.

## RQ3 correctness-qualified cold start

Define `t0` at an application request to initialize inference. `ready` occurs only after verified assets, session creation and the selected startup gate pass. Record unavailability/refusal as an outcome; do not return an artificial ready latency for a failing model. A gate pass is a measured proxy, not proof that arbitrary inputs are correct. RQ1 held-out agreement remains necessary.

For each selected supported cell, plan **20 independent process/profile starts per cache stratum**, and **100 timed steady-state requests per start** after a fixed five-request warmup. Randomize backend/cell order with seed 20261104, log temperature/power/background load and cool-down criterion. Report all 20 values, median/p95 with uncertainty and failure denominators. These counts may be revised after a documented pilot for feasibility, before held-out runs.

Cache strata: (1) fresh profile + empty application/HTTP cache, new browser process; (2) verified cached model/HTTP assets + fresh process; (3) same process/new session; (4) same session/steady state. Mark OS file-cache and GPU-driver shader-cache state as **unknown** unless controlled; a new profile is not proof of hardware-cold caches. Separate loopback-serving experiments from a reproducible shaped-network condition. Freeze bytes, server/protocol, connection reuse, cache headers, bandwidth/RTT settings and background updates. Capture actual transfer bytes and explicit CacheStorage hit/miss; Resource Timing's transferSize alone is ambiguous. Do not label loopback fetch times download performance on the public internet.

Instrument overlapping phases with monotonic performance marks: model/vocab/label fetch start/end, cache read, hash verification, runtime import/WASM fetch, WASM instantiation, session creation/graph transforms, GPU device acquisition, pipeline/shader compile where observable, first inference including readback, gate execution, and steady-state requests. Preserve wall-time boundaries and overlap; do not add overlapping durations as a total. Log first response, first checked response and first permitted send separately. Record correctness on a fixed held-out probe bank before and after warmup and every early iteration, without selecting probes based on observed failures.

Public ORT APIs generally do not expose all compilation phases separately. Application marks can measure end-to-end import/create/run time; they cannot by themselves distinguish network, graph optimization and native shader compilation. Use a separate instrumented run with WebAssembly API hooks installed before runtime import, GPU createComputePipeline/createComputePipelineAsync hooks if the runtime uses them, and browser traces. Correlate GPU queue completion/readback with the timer. Acknowledge unobservable/internal calls. Treat hooks/profiling as an instrumented cohort because overhead changes latency.

For Chromium, use trace evidence to distinguish baseline and optimizing Wasm work; [Liftoff](https://v8.dev/blog/liftoff) explains V8's tiering design, not a portable browser guarantee. Verify trace event names and any tier-control flags on the actual browser build. Compare tier-forced runs only as diagnostic experiments, with flags recorded. Do not subtract steady-state from startup and call the difference compilation time. Safari/Firefox require their own engine tracing terminology; where unavailable report combined startup cost with that limitation. Same-session warmup may combine JIT, graph optimization, shader cache and allocator effects and must not be assigned a cause without traces.

## RQ4 guards and fault injection

Implement a send-blocking state machine: UNINITIALIZED → VERIFYING → SELFTEST → READY, with FAILED/DEGRADED states after validation mismatch, timeout, device loss or model replacement. No send may race initialization or continue after a failed check. A fallback is a new verified configuration requiring its own gate. Validate output shape, finite scores, offsets, label range, truncation coverage and assets before any guard claims success.

Compare no guard, existing score-only diagnostic, enforced startup bank, per-request canary, periodic second-backend checks, and combinations. Existing score-only code is a control, not an implemented enforced guard. Freeze artifact-specific expected bank outputs and a separate PyTorch agreement policy. A strict fp32-equality gate rejects legitimate quantization differences in the existing WASM output; tune any tolerance on development data only and retain a safe/unsafe distinction against privacy annotations.

Canaries: compare a separate fixed probe request with sentinel spans inserted in the **same request** at prefix/suffix positions. Use synthetic, non-sensitive sentinels from a frozen bank. Record sentinel token coverage and whether the request was truncated. Sentinels can shift tokenization, attention and detection on the real text; measure paired recall/latency with and without them and never let a canary push sensitive text off the window. A canary passing cannot certify every token. Include faults targeted away from the sentinels as explicit counterexamples. Remove sentinel artifacts before the outgoing payload.

Spot checks: plan checking probabilities p in {0, 0.01, 0.05, 0.10, 1}, seeded independent sampling and a deterministic every-20th-request comparison. Use a different provider on the same artifact when possible; a different-precision oracle is a separate arm. Compare blocking-before-send checks against asynchronous after-send detection. The latter may detect faults but cannot prevent the already-sent leak. Measure detection delay in requests, time, and number of leaks before alarm. Startup and spot-check probes overlap neither threshold-development data nor held-out evaluation.

| Fault family | Injection site / realization | Required controls |
|---|---|---|
| Historical int8/WebGPU discrepancy | preserved artifact on a real supported device, if reproducible | retain wrong outputs and logs without injection; count as real runtime fault only after input/artifact controls |
| Asset corruption/staleness | flip model bytes, swap tokenizer/label file, stale cache mapping | hash failure vs accepted-but-wrong output separately; hash pin must cover all assets |
| Arithmetic perturbation | deterministic zeroing, sign/bit flip or scale bias in captured intermediates/instrumented runtime | record dtype, tensor/site/index, magnitude, seed; output-only corruption is labeled separately and is not a runtime root cause |
| Quantization/decoding errors | signedness/zero-point swap, wrong per-channel axis, label permutation, logits offset | paired healthy control, preserve tensors and operator attributes |
| Partial output failure | NaN/Inf, wrong shape, all-O collapse, omitted entity region, truncated tail | ensure shape/finite/truncation checks and canary-avoiding faults are evaluated |
| Temporal/persistent failure | fault at startup only, after startup, first inference only, persistent, intermittent | startup bank frozen; location/timing randomized independently of guard bank |
| Provider/lifecycle failure | GPU device loss, timeout, fallback partition changed, worker restart | distinguish explicit error from silent acceptance; failed retries cannot resend original unredacted payload |

Planned injection workload: 100 seeded location/timing trials per family and selected supported cell where the injection is meaningful, balanced across transient/persistent cases and guard arms. Report planned/attempted/activated/output-changing/harmful trial counts; faults masked before output are not detection failures. Real faults and artificial faults get separate tables. Sampling p implies no general independence-based protection guarantee. No physical hardware defect or cosmic-ray fault is claimed from software injection.

Detection rate = detected output-changing fault trials / activated output-changing fault trials, and privacy-relevant detection = blocked harmful trials / harmful trials under no-guard control. Also report alarm coverage over all activated trials. False refusal = guard-blocked requests under a healthy declared configuration / all eligible healthy requests, split harmless numeric differences, model false negatives and validation failures. Added latency is paired end-to-end send-boundary delay including check/backend startup and synchronization (median/p95 and raw N); amortized startup and maximum detection delay are separate. Include availability and oracle shared-error rates. Do not average fault families to imply natural fault prevalence.

## RQ5 public-data pipeline and restoration

Run Presidio analyzer + anonymizer locally as the **server-side architecture baseline**, with exact package/NLP-model versions, recognizers, language configuration, thresholds and policy recorded. No external server is needed for initial evaluation. Compare rule-only, native model-only, browser hybrid and guarded browser hybrid under identical label crosswalks. Report overall and per-PII-type precision/recall/full-span coverage/leaks. Dictionary terms must come from permitted train/local context, not held-out gold labels. Do not treat generic ORG/LOC/MISC success as coverage of account IDs, addresses or all sensitive quasi-identifiers.

Use a document-scoped vault with typed placeholders and explicit conversation lifecycle. Evaluate repeated values, aliases, same token in separate conversations, overlapping spans, pre-existing placeholder-looking strings, normalization, unknown/malformed/reordered/duplicated placeholders, streaming chunk boundaries and concurrent replies. Score exact restoration: correctly restored eligible placeholder occurrences / eligible occurrences, plus wrong-person substitution, unresolved and hallucinated placeholders. Unmentioned placeholders are not automatically failures when the reply task did not require them. A local echo validates transport/restore mechanics only.

For **real LLM replies**, plan a held-out set of up to 200 synthetic prompt tasks with required restored fields and reference answer constraints. Use a pinned locally running open-weight LLM with recorded model/hash/template/decoding settings, saving original redacted request, raw model reply and restored reply. This avoids any external contact. Local generation has not been run this session. A later cloud-LLM arm would require separate authorization and budget; it is not silently substituted for local execution. Score task fulfillment and restoration separately and keep failed/refused/empty replies in denominators. For natural public text, retain data access controls and avoid committing raw identifiable prompts; provide source IDs/hashes and deterministic acquisition scripts when redistribution is inappropriate.

Explicit-value redaction does not prevent sensitive-attribute inference from remaining context ([Staab et al.](https://proceedings.iclr.cc/paper_files/paper/2024/hash/9028b8a3ca98f58e373f0c1497a17448-Abstract-Conference.html)). Report it as a limitation; do not rename low exact-leak rate comprehensive privacy protection. Contextual-inference evaluation, if added, needs its own threat model and approved local data/model protocol.

Record both requested and observed provider placement. Preserve reference PyTorch tensors/logits separately from ONNX CPU outputs. Pin calibration and label policy hashes. No aggregation-only run is sufficient for final results.
